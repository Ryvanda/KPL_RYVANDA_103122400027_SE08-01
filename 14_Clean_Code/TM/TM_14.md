## 📝 Jawaban Tugas Mandiri

### Pertanyaan:
> Dari dua kode di bawah ini, mana yang kamu ingin cari masalahnya dan perbaiki di tengah-tengah malam, katakanlah jam 1 malam? Mengapa?

---

### Pilihan:
Kode yang paling saya inginkan untuk dicari masalahnya dan diperbaiki di tengah malam adalah **Kode Kedua (Clean Code)**:

```javascript
function processUser(user) {
    if (!isValidCandidate(user)) return null;
    return doSomething(user);
}

function isValidCandidate(user) {
    return user && user.isActive && user.hasPermission;
}
```

---

### Alasan Utama (Mengapa):

#### 1. Mencegah *Arrow Anti-pattern* (Pyramid of Doom)
*   **Kode Pertama** memiliki tingkat lekukan mendalam (*nested indentation*) akibat pernyataan `if` yang bersarang. Pola ini membuat alur kode bergerak secara horizontal (ke kanan), yang memaksa mata dan otak membaca kode dengan melacak banyak tingkat kurung kurawal `{}`.
*   **Kode Kedua** menggunakan **Guard Clause** (`if (!isValidCandidate(user)) return null;`) untuk menangani kondisi tidak valid di awal fungsi dan langsung keluar (*early return*). Hal ini menjaga alur kode tetap linier secara vertikal (kebawah), yang jauh lebih mudah dipahami secara visual saat lelah.

#### 2. Kognitif Load yang Rendah (Mental Capacity)
*   Pada jam 1 malam, kemampuan konsentrasi pengembang menurun secara drastis. Kode pertama mengharuskan pengembang melacak kondisi-kondisi bersarang: *"Jika user ada, lalu jika user aktif, lalu jika user punya izin, baru lakukan sesuatu, jika tidak maka kembali ke akhir untuk return null"*.
*   Kode kedua mengeliminasi beban ingatan tersebut dengan pendekatan deklaratif: *"Jika kandidat tidak valid, langsung kembalikan null. Selesai."* Logika utama `doSomething(user)` langsung dieksekusi di akhir tanpa hambatan struktural.

#### 3. Pemisahan Logika Validasi (Separation of Concerns & SRP)
*   Aturan kelayakan pengguna diabstraksikan ke dalam fungsi terpisah bernama `isValidCandidate(user)`. Hal ini membuat fungsi utama `processUser` sangat bersih dan fokus hanya pada alur bisnis (mengevaluasi kelayakan lalu memproses).
*   Jika kriteria keaktifan atau perizinan pengguna berubah di masa mendatang, kita hanya perlu mengubah logika di dalam `isValidCandidate(user)` tanpa menyentuh alur proses utama di `processUser`.

#### 4. Keterbacaan Ekspresif (Self-Documenting Code)
*   Nama fungsi `isValidCandidate` secara instan menjelaskan tujuan dari baris validasi tersebut. Pengembang tidak perlu lagi membedah maksud dari rantai `user && user.isActive && user.hasPermission` untuk mengetahui apa yang sedang divalidasi. Ini sangat menghemat energi mental saat melakukan *debugging* darurat di malam hari.

#### 5. Kemudahan Pengujian (*Unit Testing*)
*   Fungsi `isValidCandidate` dapat diuji secara mandiri dengan berbagai skenario data pengguna (null, tidak aktif, tanpa izin) tanpa harus memicu pemanggilan fungsi `doSomething(user)`.
