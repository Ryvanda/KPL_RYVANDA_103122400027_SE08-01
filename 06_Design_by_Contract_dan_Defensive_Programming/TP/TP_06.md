## 1. Analisis Perbandingan: Asersi vs Eksepsi

Dalam rekayasa perangkat lunak, terdapat dua instrumen berbeda yang sering disalahartikan namun memiliki peran yang sangat spesifik: **Asersi** dan **Eksepsi**. Memahami perbedaan filosofis di antara keduanya adalah kunci untuk menulis kode yang benar-benar *robust* dan mudah dipelihara jangka panjang.

**Asersi** pada dasarnya adalah kontrak tertulis bagi diri sendiri sebagai pengembang. Asersi mendokumentasikan dan menegakkan asumsi-asumsi yang *tidak boleh* pernah salah jika kode ditulis dengan benar. Misalnya, setelah sebuah fungsi sorting selesai dijalankan, kita bisa memasang asersi bahwa elemen pertama selalu lebih kecil dari elemen terakhir. Jika asersi ini gagal saat pengembangan, itu adalah sinyal kuat adanya *bug* pada logika algoritma kita, bukan pada input pengguna. Karena sifatnya yang hanya relevan selama pengembangan, asersi umumnya dinonaktifkan di lingkungan produksi (*production*) agar tidak membebani performa.

Sebaliknya, **Eksepsi** adalah mekanisme untuk menangani skenario yang *mungkin* terjadi di dunia nyata, terlepas dari seberapa sempurna kita menulis kode. Kegagalan jaringan, berkas yang tidak ditemukan, atau input tak terduga dari pengguna adalah kejadian di luar kendali pengembang. Eksepsi memungkinkan program untuk "jatuh dengan anggun" (*fail gracefully*), memberikan umpan balik yang bermakna kepada pengguna, dan terus berjalan ketika memungkinkan.

Garis pembatasnya adalah sederhana namun fundamental: gunakan **asersi** untuk memverifikasi invarian internal dan logika pengembang, dan gunakan **eksepsi** untuk menangani kondisi luar yang tidak terduga di runtime. Mencampurkan keduanya—misalnya menggunakan eksepsi untuk mendeteksi bug logika—akan menghasilkan kode yang menyembunyikan masalah alih-alih mengeksposnya. Perpaduan yang tepat antara asersi (sebagai "penjaga kontrak internal") dan eksepsi (sebagai "penanganan realitas eksternal") adalah ciri khas dari perangkat lunak yang berkualitas tinggi.

## 2. Implementasi Kode

Berikut adalah perbandingan implementasi fungsi pembagian menggunakan kedua metode tersebut:

### A. Menggunakan Asersi (Assertion)

Digunakan untuk memastikan input internal benar selama masa pengembangan.

```javascript
const assert = require('assert');

function divide(a, b) {
    assert(b !== 0, 'Asumsi Gagal: Tidak bisa pembagian dengan nol');
    return a / b;
}

// Output jika b = 0:
// AssertionError [ERR_ASSERTION]: Asumsi Gagal: Tidak bisa pembagian dengan nol
```

### B. Kode dengan Eksepsi (Exception)

```javascript
function divide(a, b) {
    if (b === 0) {
        throw new Error("Maaf, angka pembagi tidak boleh nol.");
    }
    return a / b;
}

try {
    console.log(divide(10, 0));
} catch (error) {
    console.error("Output:", error.message);
}

// Output jika b = 0:
// Output: Maaf, angka pembagi tidak boleh nol.
```
